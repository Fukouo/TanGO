# 测试与验证

本文说明 TanGO 1.9.1 的验证范围，便于复现测试和评估未覆盖的行为。

## 运行测试

环境准备和命令见 [开发文档](DEVELOPMENT.md#测试)。入口为 `scripts/test.ps1`，使用 JDK 17 和测试依赖 `org.json:json:20250107`。

测试使用人工构造的候选、响应和凭据；HTTPS 服务仅监听本机。无需真实 API Key，不会调用付费模型接口。

## 覆盖范围

| 测试 | 主要覆盖 |
| --- | --- |
| `LookupRulesTest` | 地址验证、假名归一化、英语候选处理、完全匹配优先、去重及 5 项上限 |
| `AiClientTest` | 模型列表、查询与详情请求、JSON 解析、错误响应、拒绝重定向、思考参数与用量采集 |
| `PlanProtocolTest` | PKCE、回调绑定、身份签名与字段校验、模型列表及流式响应处理 |
| `UsageDataTest` | Token 字段解析、缺失值、缓存计数及模型强度限制 |
| `LocalSearchTest` | 收藏模糊匹配、全半角与假名归一化、日期范围及夏令时边界 |
| `SearchLadderTest` | 自动与手动提档共享上限、最高档、未选择强度、取消及异常停止 |
| `SearchLadderHttpTest` | 提档参数实际进入 HTTPS 请求、每次用量记录、成功停止、错误不重试 |

## 1.9.1 验证结果

以下检查已通过：

- `scripts/test.ps1` 中全部 JVM 检查。
- 基础客户端的 15 次本地 HTTPS 模拟请求。
- 提档逻辑的 20 项检查，以及 14 次本地 HTTPS 请求中的 39 项检查。
- Android 资源编译、Java 编译与 D8 转换。
- APK 的 `zipalign` 对齐和 v2/v3 签名校验。

未指定思考强度时，查询流程在发出网络请求前要求选择明确档位。旧的空值设置不自动改为其他强度。

## 验证边界

本地模拟检查验证程序对既定输入和响应的处理，不能证明模型能正确识别某个词、返回正确释义，或在更高强度下提升召回。

以下项目仍需要实际设备或服务验证：

- 真实账号授权、套餐可用性、模型与思考档位支持。
- 真实查询的词义质量、近似词和略语召回、Token 消耗。
- Android 设备上的数据库升级、凭据持久化、键盘、旋转与触摸操作。
- 不同屏幕、字体缩放和启动器图标蒙版的显示效果。

验证报告应分别标明本地模拟、真实服务与设备测试的结果，避免混淆。
